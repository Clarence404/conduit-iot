## 实施决定

1. V8 扩展授权表并保留旧 role/JWT；兼容账号采用 authz_managed=false，首次保存绑定后显式接管。空绑定永不回退旧权限。原 spec 一次性迁移旧用户的方案细化为此方式，以覆盖 Flyway 之后启动创建的管理员和新用户。
2. 请求链：身份/平台边界、TenantContext、PermissionGateFilter、AuthorizationService；MyBatis-Plus 顺序为租户、数据范围、分页。范围只用可信数据库数值 ID，解析失败拒绝执行；控制器不自行拼授权条件。
3. 列表/总数/详情/写操作共用 SQL 范围，跨范围详情 404。共享产品只允许租户级管理；新建项目同样需要租户级权限。停用项目/站点下设备与资产写入拒绝，产品删除的依赖检查仍须包含停用组织内设备，避免级联误删。
4. 权限直接回源 PostgreSQL，无 Redis 缓存，无 av/sid 新声明；每请求撤权生效与会话吊销是不同能力。后台接入继续沿可信设备租户处理，事务断言不改动。
5. shadow 保留旧授权并观察差异；enforce 执行；read-only 保留范围并拒绝写。已接管账号后不允许回退旧应用/旧全权授权。
6. 保留租户所有者；普通租户管理员不能授予/修改所有者；新授权权限须属于操作者。绑定替换与用户降权沿用租户行锁。删除仍有成员绑定的项目/站点以及跨项目移动已绑定站点时拒绝。
7. 每个新功能必须准备演示数据，已写入全局 AGENTS.md 与项目 CLAUDE.md。本次用版本化 demo API 脚本建立 A可写/B只读/C不可见，账号凭据不塞进 Flyway，动态数据用模拟器生成。

## 验证与交付

执行真实 PostgreSQL/Redis/InfluxDB 集成测试、完整 Maven 回归、前端测试/构建和 enforce 下可靠性 E2E；失败不通过放宽范围/事务断言规避。同步 README、CLAUDE.md §1.2/§4、授权架构 SVG、API 使用与部署说明、spec 状态和测试报告。
