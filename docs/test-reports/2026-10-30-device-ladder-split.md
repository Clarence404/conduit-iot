## 判据

> 实测会差 ±261 条，曾把 5,000 档误判为失败；改为上述 InfluxDB 行数判据。

## 发现一：鉴权回调偶发失败（已修复）

修复前 5,000 档有 1 台设备鉴权被拒。EMQX 日志：`http_connector_do_request_failed, reason: closing`，server 端没有收到请求。
EMQX 以 8 条 HTTP 长连接回调鉴权（`pool_size` 8、`enable_pipelining` 100），空闲时不关；Tomcat 默认空闲约 20 秒或同一连接满 100 个请求即关，
EMQX 恰在关闭瞬间复用该连接时请求失败、不重试、直接判未授权（发生在两档之间空闲一分多钟后的第一批建连）。
修复：`server.tomcat.keep-alive-timeout: 30m`、`max-keep-alive-requests: -1`（`69ac212`）。修复后 1 万～2 万档 EMQX 日志鉴权回调失败均为 0。
生产影响：设备偶发一次鉴权失败，真实设备会重连，不丢数据。

## 发现二：30,000 档 EMQX VM 的虚拟网卡挂死（测试环境限制）

EMQX VM 内采样（每 30 秒，未断档）显示 TCP 连接数：12:44:53 达 24,795 后不再增长，12:47:23 掉到 10,807，12:48:23 仅剩 8；期间可用内存 5.3 GB、EMQX 内存 1.6 GB，并非内存耗尽。
内核日志：

```
04:44:33 kernel: workqueue: e1000_watchdog [e1000] hogged CPU for >10000us 16 times
04:47:14 kernel: TCP: too many orphaned sockets
05:26:40～05:27:23 kernel: e1000 0000:02:01.0 ens33: Detected Tx Unit Hang   （每 2 秒一次，持续到恢复）
```

EMQX VM 使用 VMware 的**模拟网卡 e1000**（应用 VM 为半虚拟化 vmxnet3）。约 2.5 万条连接时 e1000 发送队列挂死，VM 收发全断（连 ping 也不通），
设备连接因保活超时被全部断开（`too many orphaned sockets` 即其后果）。VM 内系统与 EMQX 进程始终在运行（容器未重启），网卡恢复后自动重连。
**这是测试 VM 的网卡类型限制，不是 EMQX 或 Conduit 的上限。** 换 vmxnet3 后再测 3 万台以上。
