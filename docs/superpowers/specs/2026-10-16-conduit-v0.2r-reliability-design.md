# Conduit V0.2-R 设计：可靠性加固

- 日期：2026-10-16
- 状态：已实现（2026-10-16）
- 范围：V0.2-C 之后的可靠性子项目（路线图 V0.2-R）：EMQX 磁盘持久会话、transport 单活多备、e2e 独立环境与四个故障场景、模拟器多租户多产品。
- 前置：V0.2-C 已完成。transport 现用共享订阅 `$share/<组>/conduit/+/+/up/#`、持久会话保留 1 小时；本地 transport 会话保留 0；e2e 依赖 Docker 中的 `conduit-server` 容器，开发模式下无法运行。

## 1. 背景与实测

transport 离线时消息积压在 EMQX 内存会话中。2026-10-16 在 EMQX 5.8.6 开源版上实测（订阅方离线期间发布 2000 条 QoS1）：

| 配置 | 重连后收到 |
|---|---|
| 现配置，普通订阅 | 1000（内存队列上限 `max_mqueue_len = 1000`） |
| 现配置，共享订阅（transport 当前方式） | 500 |
| 开启磁盘持久会话，普通订阅 | 2000 |
| 开启磁盘持久会话，共享订阅 | 订阅被拒：`Shared Subscriptions not supported` |

结论：5.8.6 的磁盘持久会话有效，但与共享订阅互斥，因此采用「磁盘持久会话 + transport 单活多备」；多实例共享订阅放弃，升级 EMQX 以同时支持两者留待 V1.0 评估。开启磁盘持久会话要求 `cluster.discovery_strategy = singleton`（单节点）。

## 2. 目标

- 杀 server、杀主 transport、杀全部 transport（离线期间设备照常上报）、重启 EMQX，四种情况下数据都不丢（e2e 计数恰好等于发送数）。
- e2e 在完全独立的临时环境中运行，不影响开发环境，随时可跑。
- 演示环境所有租户的设备都有合理的模拟数据。

不包含：多实例并行消费（吞吐扩展）、EMQX 升级、设备端离线缓存（由设备负责）。

## 3. EMQX 与 transport

### 3.1 EMQX

- compose 中 EMQX 增加 `EMQX_DURABLE_SESSIONS__ENABLE=true`、`EMQX_CLUSTER__DISCOVERY_STRATEGY=singleton`；消息保留期沿用默认 1 天（`durable_sessions.message_retention_period`）。
- 现有数据卷沿用，重启生效；设备会话一并持久化，对设备无影响。

### 3.2 transport

- 订阅改为普通订阅 `conduit/+/+/up/#`；`$SYS` 上下线事件照旧。
- 所有实例共用固定 clientId（配置 `conduit.transport.mqtt.client-id`，默认 `conduit-transport`），`cleanStart=false`，会话保留 86400 秒（与 EMQX 保留期一致）。
- 删除共享订阅组配置（`share-group` 等）；本地开发不再要求 `session-expiry-seconds: 0`。

### 3.3 选主（单活多备）

- Redis 键 `conduit:transport:leader`，值为实例 id（主机名 + 进程号 + 随机串），`SET NX PX 15000` 抢锁；主实例每 5 秒用 Lua「比对 id 后续期」。
- 实现偏差：抢锁用 Lua 脚本，键值已是本实例 id 时刷新 TTL 视为重新获得，否则 `SET NX PX`；健康检查的 `connected` 在订阅获批之后才为 true。
- 只有主实例连接 EMQX；备实例每 2 秒尝试抢锁，不连接 EMQX。
- 续期失败（Redis 不可用、id 不符、续期超时）→ 立即断开 MQTT，转为备用；Redis 不可用时所有实例都不连接（不会出现无锁的主实例）。
- 新主用同一 clientId 连接时 EMQX 踢掉旧连接，作为天然的防双主保护；切换窗口内的少量重复消息由后续写库去重（同设备同时间戳覆盖）。
- 正常停止时主动释放锁（比对 id 后删除），备实例可立即接管。
- 健康检查（actuator health 详情）显示 `role: LEADER | STANDBY`；选主、续期失败、切换写 INFO/WARN 日志。
- 配置：`conduit.transport.leader.ttl`（默认 15s）、`renew-interval`（5s）、`acquire-interval`（2s）。

### 3.4 部署

- 完整部署（`build-local.sh`，`app` profile）起 2 个 transport（compose `deploy.replicas: 2` 或两个服务定义，按 compose 兼容性选择），一主一备。
- 开发模式 IDEA 中一个 transport，直接成为主实例。

## 4. e2e

### 4.1 环境（测试自动搭建与清理）

- Testcontainers 在 Docker 宿主机上起 PostgreSQL 16.8、Redis 7.4.2、InfluxDB 3.12.0-core、EMQX 5.8.6（开启磁盘持久会话、单节点；鉴权回调指向测试机上的 server），端口随机，与 `conduit` 开发环境互不影响。
- 测试机本地以 jar 启动 1 个 server、2 个 transport，连接上述临时环境；进程由测试启动、强制结束与重启。
- 环境变量 `E2E_DEV_HOST`：Docker 宿主机访问测试机的地址（EMQX 鉴权回调用），未设置时测试失败并说明原因；其余沿用 `DOCKER_HOST` / `TESTCONTAINERS_HOST_OVERRIDE`。
- 设备由测试代码扮演：每个场景一个新产品（中文名，如「e2e 场景 1 电表」）与 10 台设备，每台 50 条 QoS1，共 500 条；未收到 PUBACK 时重发、断线自动重连（模拟真实设备）。

### 4.2 场景

| 场景 | 操作 | 验证 |
|---|---|---|
| 1 杀 server | 发送中途强制结束 server 进程，数秒后重启 | 未确认消息被重新认领处理 |
| 2 杀主 transport | 发送中途强制结束当前主 transport | 备实例接管，磁盘积压补齐 |
| 3 杀全部 transport | 两个都结束，设备继续上报约 20 秒后重启 | 磁盘持久会话兜底 |
| 4 重启 EMQX | 发送中途重启 EMQX 容器 | 设备与 transport 重连，会话与积压不丢 |

每个场景断言：InfluxDB 中该产品恰好 500 条；死信流中没有该产品的记录；消费组中没有该产品的未确认消息。场景结束清理所建数据（产品、设备）。

### 4.3 运行

`mvn -B verify -Pe2e -pl conduit-e2e -am`（需先打包 jar），预计 6～10 分钟；不进默认构建。原依赖 Docker 中 `conduit-server` 容器的 e2e 删除（由场景 1 取代）。

## 5. 模拟器多租户多产品

### 5.1 发现（启动时一次）

1. 保留现有逻辑：用 `admin` 确保默认租户的「三相电表（演示）」及其设备存在、演示物模型补导。
2. 用平台管理员（新配置 `SIM_PLATFORM_USERNAME` 默认 `sysadmin`、`SIM_PLATFORM_PASSWORD`）登录，列出启用中的租户，按 `SIM_TENANTS` 过滤（默认 `*`，逗号分隔租户编码）。平台密码为空时跳过多租户模拟，只模拟演示产品。
3. 逐个进入租户，取物模型非空的产品及其启用设备，每产品最多 `SIM_MAX_DEVICES_PER_PRODUCT`（默认 100）台；演示产品按原逻辑处理，不重复。
4. 重置这些设备的密钥并连接；上报格式按产品解码器（`standard-json` / `flat-json`）。
5. 退出租户后继续下一个；任一租户失败只记 WARN，不影响其他租户。

### 5.2 数据生成

按物模型逐测点生成，取值满足上下限与小数位（不会被 `FIELD_REJECTED`）：

| 识别依据（标识/名称/单位） | 规则 |
|---|---|
| 电压（V） | 220 附近小幅波动，三相略有差别 |
| 电流（A）、有功/交流功率（kW，非光伏） | 按日用电曲线变化 |
| 光伏功率、辐照度（W/m²） | 6～18 点正弦日照曲线 × 容量，夜间 0，叠加云层扰动 |
| 累计量（kWh、m³，标识或名称含累计/total/EP/energy） | 单调递增，增量与对应功率/流量相符；日发电量（eday/日）每天零点归零 |
| 温度（℃） | 环境温度有昼夜变化；设备温度（绕组、机内）随负载升高 |
| 流量（m³/h） | 早晚用水高峰 |
| 水压、pH、浊度、余氯、湿度、PM2.5、CO₂、风速 | 合理范围内缓慢漂移 |
| 枚举 | 多数时间取正常值（标签含 运行/发电/开启/正常，否则第一个值），偶尔切换，同设备一小时内不变 |
| 布尔 | 多数为否，偶尔为是 |
| 其他 | 上下限内随机游走；无上下限按单位推断范围，再无则 0～100；INT 取整；TEXT 跳过 |

每台设备的状态（累计量、游走当前值）保存在内存，重启后从合理初值开始。

### 5.3 注意

模拟器会重置所模拟设备的密钥，只应对演示租户使用；`SIM_TENANTS` 限定范围，README 写明。

## 10. 已知问题（2026-10-16）

- 主 transport **正常停止**（发送 DISCONNECT）时，停止瞬间已收到未 ACK 的消息在新主接管后被 EMQX 5.8.6 磁盘持久会话以错误内容重发（重发的是早已 ACK 的旧消息），导致少量丢失；强杀不复现。详见 `docs/backlog-v0.2.md`「V0.2-R 遗留」，单独处理。
