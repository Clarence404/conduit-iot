# 智能体交接约定

跨智能体或跨任务继续尚未完成的工作时，在本目录维护一份 `YYYY-MM-DD-<主题>.md`。同一任务只更新这一份；普通已完成任务无需空交接。接手者先读交接，再用 Git、测试报告、部署环境重新核实，不能把旧记录当成实时状态。

交接文件须写清：

1. 目标与完成标准，已获用户授权的范围，以及明确暂停或不做的事项。
2. 分支、提交、工作区状态；代码、VM、数据库各自实际运行的版本，注明核实时间。
3. 已完成动作及证据（测试报告、日志、演示入口）；失败、未执行和不确定项分别标明。
4. 下一位智能体可直接执行的步骤、验证命令、预期结果、回滚或恢复位置。
5. 演示数据的初始化方式与资源名称；外部依赖、凭据的**安全获取方式**，不记录密码、令牌、私钥或包含这些值的命令输出。

每次交接前更新状态。接手后先核对现状，再继续操作；发现与交接不一致时在文件中修正并说明。任务完成时标记「已完成」并链接最终测试报告和提交，不留下看似仍待处理的清单。`docs/handoffs/` 是执行状态，不替代 spec、roadmap、架构文档和测试报告。
